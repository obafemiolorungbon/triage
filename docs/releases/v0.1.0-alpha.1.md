# Triage v0.1.0-alpha.1

Triage is now available as a public developer preview: a self-hosted feedback
intake and triage system for product, support, and engineering teams.

This release is meant for builders who want to run the stack locally, inspect
the architecture, deploy their own feedback workflow, and contribute to the
open-source roadmap.

## Highlights

- Embeddable feedback widget with configurable forms, branding, consent,
  targeting, triggers, and image attachments.
- Internal dashboard with table/Kanban queue views, ticket preview drawers,
  ticket detail pages, notifications, and cleaner feedback actions.
- AI-assisted classification with metadata-aware escalation and safe fallback
  behavior when model credentials are not configured.
- Knowledge-base article management and deflection support.
- Linear and Jira handoff paths for feedback that should become product work.
- Docker/local development path with Postgres, Redis, MinIO, backend, worker,
  dashboard, marketing site, and playground.
- Demo seed data for a usable first-run workspace.
- OSS-ready repository structure: MIT license, contributing guide, security
  policy, issue templates, PR template, Dependabot, changelog, CI, and release
  notes.

## Install

```bash
git clone https://github.com/obafemiolorungbon/triage.git
cd triage
pnpm install
cp .env.example .env
docker compose up -d postgres redis minio minio-init
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Dashboard: http://localhost:3000

Marketing site: http://localhost:3001

Widget playground: http://localhost:3002

API: http://localhost:4200/api/v1

## Alpha Notes

This is a developer-preview release. It is suitable for evaluation, local
development, self-hosted experimentation, and contribution. Before using it for
high-volume or regulated production workloads, review the security policy,
deployment guide, and roadmap items around captcha, encrypted widget secrets,
retention automation, observability, and public status links.
